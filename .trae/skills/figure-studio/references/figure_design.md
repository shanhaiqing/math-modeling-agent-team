# 图设计卡判据（出图步骤 0，不可跳过）

> 核心思想（Icarus-Figures §0a Figure Contract 与 DRZ-hang/paper-figures Stage 2 收敛验证）：
> **先想清楚"这张图要论证什么"，再决定编码与构图，最后才写代码。**

## 一、一句话职责（必填，写不出不画）

每张图先写：**"This figure shows that ___."**（这张图论证了 ___）。

- 写不出这句话 → 此图无存在必要（凑数图信号），删除或合并。
- 一句话含两个"并且" → 拆成两张图（一张图一个核心结论）。

## 二、设计卡字段（每张核心图一份，写入 handoff 或图表清单）

| 字段 | 填写要求 |
|---|---|
| **core_claim** | 一句话职责（上节） |
| **数据结构** | 输入数据的形态（单曲线/双变量/分组分布/矩阵/序列…），n 多少 |
| **编码映射** | x / y / 颜色 / 大小 / 线型 / 分面 **各映射哪个量**——颜色必须编码一个数据维度（时间/组别/第三变量），禁止仅作装饰 |
| **图型与备选** | 首选图型 + 1 个备选（查《图表类型参考库》决策表），一句话理由 |
| **标注清单** | 图上要标什么：关键数值/阈值线/临界点/置信区间/n/误差类型 |
| **正文引用位置** | 此图将在哪一节哪一句被 `\ref{}` 引用（无引用位置的图不画） |
| **数据来源** | solution.json / results JSON 的具体字段路径（图上数值的溯源锚点） |

## 三、hero 图（每篇 1-2 张，指定即投入）

全篇图表中指定 1-2 张 **hero 图**——评审第一眼记住的那张。判定标准：承载论文最核心论证（如最优性权衡、策略临界点、方法框架）。hero 图要求：

- 编码维度 ≥3（如 x/y + 颜色第三维 + 标注），信息密度显著高于普通图；
- 必须过 `visual_review.md` 的四轴验收（Depth·Elegance·Unimpeachable·Visible gap）；
- 打磨投入 ≥3 倍于普通图（至少一轮"读图→回改→重渲"）。

## 四、同一批数据、不同论点 → 不同图（对照示例）

| 数据 | 论点 | 应选图型 |
|---|---|---|
| 两情景 2000 次仿真生存率 | "两情景均值差异显著" | 带 CI 误差棒的柱状对比 / 点估计+区间 |
| 同上 | "生存率分布是双峰的" | 直方图 / 雨云图（分布形态） |
| 参数扫描 10 点 | "结论对参数不敏感" | 折线叠加 + 基线虚线 |
| 同上 | "策略在某临界值翻转" | 阶梯线 + 临界点竖线 + 标注 |

> 论点先于图型：先写 claim，再查《图表类型参考库》选型；同一数据换个 claim 往往就换一张图。
