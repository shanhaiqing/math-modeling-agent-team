# 出图验收：程序自检 + 人工感知层（出图步骤 4–5）

> 四层验收：形式层（机查已覆盖）→ 程序层（visual_qa 零 token）→ 感知层（**HG1 人工看 PNG**）→ 卓越层（四轴，hero 图由人在 HG1 过）。
> **禁止任何模型 Read 生成 PNG/PDF。** 感知层清单供人用，不供 AI 读图循环。题面源图 `赛题/题面图/` 不在此禁令内。

## 一、程序层：visual_qa 程序自检（导出前必跑）

绘图代码末尾调用：

```python
from visual_qa import audit_figure
problems = audit_figure(fig)   # 缺字形/文本裁切/刻度重叠；shuwei_en 另禁图内 CJK
assert not any(lv == "ERROR" for lv, _, _ in problems)
```

ERROR（空图/缺字形/完全越界；**`shuwei_en` 另含图内 CJK**）未清零**禁止导出**；WARN（部分裁切/刻度重叠/dpi）逐条交 HG1 人工看图裁定。

## 二、感知层：人工 8 项清单（HG1 打开 PNG，模型不得 Read）

1. 图例是否压数据/压曲线？
2. 标注框是否与数据点、刻度、其他标注重叠？
3. 多面板的 (a)(b) 标签是否对齐、子图间距是否均匀？
4. 坐标轴标签+单位是否齐全？刻度数字是否完整可读（未被裁切）？
5. 配色在灰度打印下是否仍可区分（线型/marker 冗余编码兜底）？
6. 图内最小字号在最终展示宽度下是否可读（≥ 正文字号 70% ≈ 9pt，<0.9\textwidth 展示的图要按缩放折算）？
7. 图实际内容与设计卡 claim 是否一致——图真的论证了那句话吗？
8. 正文将对图内元素的引用（颜色/方位/子图标签）能否与图对得上？（成稿后再由 HG2 对照 PDF）

任一项不过 → 人在 HG1 退回 FIGURES：改绘图代码后重渲（禁止在图上手动遮盖/拼接），再过程序层，再交人看。

## 三、卓越层：四轴验收（仅 hero 图必过，普通图鼓励；由 HG1 人工判定）

| 轴 | 判据 |
|---|---|
| **Depth（有深度）** | 编码维度 ≥3；一张图能支撑一段论证而非一个数字 |
| **Elegance（优雅）** | 无默认感：配色/线宽/标注经设计；去掉任一元素都损信息 |
| **Unimpeachable（无懈可击）** | 单位/n/误差交代齐全；坐标轴选择（截断/对数）在 caption 有声明 |
| **Visible gap（明显差距）** | 与"默认 matplotlib 直出图"相比一眼可辨的打磨痕迹 |

四轴有两项明显短板 → hero 图未达标，HG1 退回重绘或降为非 hero。

## 四、回改协议（仅在人指出缺陷后）

HG1 / HG2 指出问题 → 定位到绘图代码（禁止在图上手动遮盖/拼接）→ 修改后重渲 → 再跑程序层，观感再交人看。
**至多 3 轮**；3 轮仍不过的图降级（换更简单的图型）或降级为非 hero 图。

## 五、按最终尺寸出图（防字号失真的唯一正确做法）

- `figsize` 直接设论文最终展示尺寸（0.9\textwidth ≈ 14.6cm = 5.75in，即 `vs.CU_TEXTWIDTH_IN`），**禁止导出大图再到 LaTeX 里缩放**——缩放会让设计好的字号等比失真。
- 图内字号设定以"最终展示宽度下 ≥ 正文字号 70%（≈9pt）"为下限。
- 正文侧图幅规范（0.9\textwidth 统一）见《LaTeX格式规范》§四；两侧联动：绘图 figsize 与 LaTeX 引入宽度按同一尺寸设计。
