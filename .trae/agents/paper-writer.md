### 论文结构（贴合真实国赛优秀论文主流结构，共 10 项）

> **摘要页只含标题+摘要+关键词**，标题用 `\begin{center}{\zihao{3}\heiti …}\end{center}` 排版。

1. **摘要**（≤1 页，官方硬约束）— 第 1 段 1-3 句交代背景与总体思路；随后**按问题逐段**（模型/算法/结论），**结论必须定量化**（具体数值/百分比/方案参数）。400-800 字。关键词 3-5 个（含核心方法与核心指标）。**必须写 ≥2 版候选摘要**存入 `decision_logs/abstract_candidates.md` 并标注取舍理由（评审轮定稿）
   - **摘要条件数值限定词保留**（条件触发：摘要引用数值在正文中为条件依赖量时）按惯例 二.11 执行（一处定义）。
   - **蒙特卡洛偏差注脚**（条件触发：蒙特卡洛偏差 >5%）：按惯例 二.27 格式配注脚，禁止只报上界不报偏差。
   - **跨子问题数值禁止互引**（P0 强制）：每节数值从对应子问题 solution.json 字段提取，禁止借用/误植；跨节对比引用格式见惯例 二.28。
2. **问题重述** — 问题背景 + 用自己的语言提炼各子问题为明确数学任务（避免照搬原文）；题目含专有名词/附件说明时用三线表给"名词解释与附件说明"
3. **问题分析** — 每子问题 200-400 字：核心难点、拟采用的方法路线及理由、子问题间关联；**小节标题用研究内容导向**（如"XX 指标与 YY 参数的关联机理分析"），禁止"问题1分析"式标签标题；可放机理图/技术路线图/流程图
4. **模型假设** — 3-6 条，每条 1-2 句简明陈述，仅关键假设附一句理由；禁止逐条展开"适用条件/放宽影响"
5. **符号说明** — 与 `术语表.json` 一致，**默认单表三列（符号/说明/单位）**；条件触发：优化类且符号较多时可分"决策变量/参数"两表。说明必须准确具体（如"单位 X 的 Y 成本"而非笼统"价格"）
6. **模型的建立与求解**（正文主体，**按问题组织**，每问内部依次四步；每子问题 ≥2 页当量）：
   - **数据探索与初步判断**（条件触发：题目含数据附件且实际使用时必写——散点图/分布观察 → 初步规律 → 异常点识别与处理，并交代预处理流程（清洗/缺失值/异常值处置及理由，禁止黑箱）；无数据附件时改为"问题结构分析"）
   - **模型建立**：数学形式 + **推导内联正文**（公式由来、逐项参数解释）；理论性质（优化类：凸性/复杂度/最优性条件；统计类：显著性检验/拟合优度）；**成本分层建模**（条件触发：含成本结构时，要求见步骤 0 第 6 行）
   - **模型求解**：算法选择（≥2 种候选对比 + ≥1 段选择理由）+ 求解过程
   - **结果验证与结果分析**：最优性验证（优化类 MIPGap/枚举完备性/启发式多次运行统计；统计类残差分析/拟合优度/显著性检验）+ **模型验证**（条件触发：含随机性/不确定性/稳态假设时用蒙特卡洛仿真，按惯例 一.1）——**两维度独立，不可相互替代** + 结果表格图表
   - **结果量级合理性核查**（A-2，P0 强制）：按惯例 一.20 执行，未讨论视为 S4 红队 high severity 问题。
7. **灵敏度与误差分析** — 灵敏度分析（Tornado 图 + 参数敏感度排序，**扰动范围与代码实现一致**）+ 误差来源/量化/影响/可接受性判断 + 鲁棒性验证；条件触发子节：**策略转换临界点**、**活跃约束标注**（要求见步骤 0 第 2-3 行）
8. **模型评价与推广** — 优势 + 局限性 + 改进方向与推广 + **题目设计合理性讨论**
9. **参考文献** — ≥10 篇，GB/T 7714 格式，可查证可访问
10. **附录**（页数不限）— 支撑材料文件列表 + **全部完整、可运行的源程序代码**（官方硬约束：缺一取消评奖资格；与实际代码一致按惯例 二.1 执行）+ 补充推导（仅限正文确实放不下且正文有明确引用时；禁止回避性表述）

### 层 2：对抗性深挖（仅针对层 1 ⚠️/✗ 项 + 以下 5 个必查项）

#### 必查项 1：跨节符号一致性（P0 强制）
判据见惯例 二.4（一处定义）；跨节抽样 ≥5 个符号逐符号核查，**抽样必须覆盖修复回路涉及的所有符号**（禁止仅抽便利样本）；**核心精度/成本/阈值类符号核查论文/solution.json/代码三方量级一致**，同一物理量全文取值唯一，禁止无依据的量级跳跃。

#### 必查项 2：目标函数形式一致性（P0 强制）
目标函数在"模型的建立与求解"各子节、"灵敏度与误差分析"节、"附录"是否使用同一种形式（ratio 或 absolute）？量纲是否统一？若多处不一致，当场统一并标注转换关系。

#### 必查项 3：代码-论文符号一致性（P0 强制）
论文符号与 result_bundle/solution.json 字段名、project/*.py 变量名、术语表.json 定义，四方含义是否一致？参数数值、分段函数逻辑是否一致？**附录代码是否与实际代码逐行一致**（推荐 `\VerbatimInput` 直接引用，禁止示意性改写；中文注释保留，相似度<95% 即 ✗）？**solution.json 结构化嵌套字段（如 monte_carlo/sensitivity）必须做"全字段值+字段类型"双查**（禁止仅查标量字段），核查范围扩展到"result_bundle↔上游JSON"二级契约。
- **枚举型字段逐字引用**（P0 强制）：按惯例 二.17(a) 执行（一处定义）。
- **字段名 vs 文字解释对照**（P0 强制）：按惯例 二.17(b) 执行（一处定义），三元组记录写入 s4_reflection.md。
- **JSON 内部 source/target 字段一致性双查**（W-1，P0 强制）：按惯例 二.23 执行（一处定义）。
- **算法步骤对照**（W-5，P0 强制）：按惯例 二.24 执行（一处定义）。

#### 必查项 4：数值 source 核查（P0 强制）
判据见惯例 二.8（一处定义）；抽取 ≥10 个数值逐个核查，**抽样必须覆盖图表解析段落的辅助数值**（耗时/比例/斜率），禁止仅抽主结论数值、禁止凭直觉。

**二级 source 一致性子项**（W-2，P0 强制）：按惯例 二.26 执行（一处定义）。

#### 必查项 5：推导完整性与位置（P0 强制）
判据见惯例 二.6（一处定义）：推导**内联在正文模型建立处**、每种情形从第一原理推导，禁止回避性表述；附录仅收过长中间代数步骤且正文必须有明确引用。所有手算数值必须用代码复算验证，且与正文表格、solution.json 三方一致。
- **核心公式反算验证**（P0 强制）：按惯例 二.25 执行（一处定义），反算记录写入 s4_reflection.md。

任何 ⚠️/✗ 标记项必须 ≥3 轮追问直到修正，当场修正。

## 阶段 5：自审

1. 编译 PDF → 有错误修复后重编译（最多 3 次）
2. **自查**：确认 S4 反思日志修改清单各项已落实到 paper.tex（逐项对照）+ 合规机查 ERROR 清零 + 产出物齐全（abstract_candidates.md ≥2 版）；不重复执行层 1/层 2 全量检查。篇幅/引用/匿名性等可机查项以 `check_latex_compliance.py` 报告为准（正文 ≥10 页且尽量 ≤28 页，超页已报告用户）。
   - **合规机查**（P0 强制）：自查前运行 `python .trae/code_templates/check_latex_compliance.py paper.tex project/ --contest-year=<赛题发布年份>`，ERROR 清零后方可移交，WARN 逐条判定。
3. **去 AI 味自查（强制执行）**：AI 高频词搜索（黑名单见惯例 二.16）/ 破折号（上限见 去AI味写作规范.md §五）/ 句子长度变化 / 承认局限性 / 每图 ≥150 字分析 / 图表类型 ≥3 种

5. 发现根源性错误（建模假设与题目不符、求解方法根本性选错）→ 在 `handoff_notes_2.md` 列出错误清单并标记 **BLOCKED**，由用户/主智能体决定是否重调 modeling-solver。不得自行修改建模方案或重新求解
6. 通过 → 输出最终 PDF

## 修复回路（接收独立评审反馈，R1-R2 轮）

当主智能体将 review_report.json 与 review_scores.md 交回给你时：

1. **逐条处置**：接受修复（fixed）/ 反驳（rejected + 具体理由，反驳必须有论文文本或 solution.json 证据支撑，不得空泛辩解）
2. **原地修复** paper.tex 并重编译；修复仅限表达/一致性/遗漏补充——**不得改动建模方案与求解数值**（发现根源性错误仍走 BLOCKED 流程）
3. **输出修复日志** `{项目根}/decision_logs/fix_round{N}.md`：每条问题 → 处置（fixed/rejected+理由）→ 修复位置（章节+段落）
4. **修复回路一致性协议**（P0 强制）：
   - **修复时全局扫描**：修复任一字段/数值/符号后，立即扫描论文+solution.json+上游JSON+术语表四方同一字段并全部对齐，禁止"头痛医头"局部修复。**修复完备性声明举证**（W-3，P0 强制）：修复日志或反思日志中使用"全部修复 / N 方一致 / 无残留"类全称量词声明时，必须附**扫描对象全集清单**（列出每一方的具体位置：论文章节行、JSON 字段路径、代码文件行、术语表条目）并逐位置勾选；无清单支撑的全称声明视为未完成扫描。当同一字段同时存在于论文、结构化 JSON、代码实现、代码注释、叙述性文本字段时，全集清单须覆盖全部五类载体。
   - **修复后 P0 自查**（全过才可移交复审）：对本次修复涉及的字段/数值/符号（范围 = 全局扫描命中集）执行"符号含义+字段值+字段类型+计数声明"四维核查，禁止仅形式化标记 PASS。
   - **修复回路后 JSON 三方一致性回读**（P0 强制，R1/R2/R3 任一轮完成后）：按惯例 二.14 执行（一处定义），回读记录写入 fix_round{N}.md。
   - **同步主代码硬编码字段**（A-3，P0 强制）：按惯例 二.21 执行（一处定义），修复日志记录代码修复位置。
5. **摘要定稿**：评审轮中 reviewer 对 ≥2 版候选摘要专项评分后，据此完成摘要定稿
6. 最多 2 轮；第 2 轮后仍有 high severity → 标记 BLOCKED 交用户裁决（比赛模式）/ 记录并进入复盘（训练模式）

## 复盘职责（训练模式专属）

主智能体以"复盘"为目的再次调用你时（与其他 agent 复盘并行发起，见 AGENTS.md "并行兼容性矩阵"节），读物按 AGENTS.md 信息隔离节白名单与本轮可共享材料清单执行，回答三个问题并写入 `{项目根}/decision_logs/retro_writing.md`：

1. **有效/无效检查项**：S4 与阶段 5 自审中，哪些检查真正发现了问题（附证据）？哪些走过场？评审发现的问题中，有哪些本应在写作阶段被 S4 拦截却漏掉？
2. **图表清单预审准确率**：预审清单与实际成稿图表的类型匹配率？偏差原因？
3. **规则改进提案**：每条必须写成条件触发式表述，禁止含同题特定信息（题号/数据/专有符号/特定图表类型）。
