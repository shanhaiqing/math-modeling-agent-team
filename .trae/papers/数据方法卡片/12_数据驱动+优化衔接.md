# 12 数据驱动 + 优化衔接

> 数据方法卡片。Agent 1 阶段 2-3 使用；"数据建模产出 → 优化/决策模型输入"的接口规范（C 题高频形态：先预测/评价，后决策）。

---

## 概述

许多 C 题的形态是：子问题 1-2 用数据方法（预测/评价/分类），子问题 3 把数据结论作为参数/约束/目标输入决策模型。衔接处是最易断裂的地方：**数据产出的口径、不确定性、有效期必须显式传递**，优化端须声明对输入误差的敏感性。

**接口三问**：
```
传什么（哪些量：预测值/概率/得分/簇标签/参数估计）
什么口径（定义、单位、时间粒度、样本范围）
有多准（点估计 + 区间/误差带，供优化端做敏感性）
```

---

## 适用场景

| 特征 | 判断条件 |
|------|---------|
| 触发条件 | 特征指纹 `downstream_optimization = yes`，或题目出现"在预测/评价基础上制定…" |
| 典型形态 | 预测需求 → 库存/补货决策；风险评分 → 额度/定价；评价得分 → 资源分配；分群 → 差异化策略 |

---

## 下游模型族分叉（强制）

`downstream_optimization=yes` 时，必须在 `feature_fingerprint.json` 与 `modeling_plan.json` 填写 **`downstream_decision_kind`**（多子问时：任一问能写出决策变量+目标+约束，则取 `structured_planning`）：

| 取值 | 判据 | 决策端做法 |
|------|------|-----------|
| `structured_planning` | 能写出决策变量 + 目标函数 + 约束 | 建立规划模型并用开源求解器求解。可以点名使用 `mip_solver.py`。**禁止**用监督学习拟合代替决策器，**禁止**改调优化建模岗。 |
| `rule_threshold` | 阈值 / 评分卡 / 规则表 | 自实现决策规则 + 阈值扰动 |
| `queueing_simulation` | 到达/服务过程 + 策略评估 | 分布拟合（卡片 09）+ 蒙特卡洛；**禁止**再回归一个「最优等待」 |
| `na` | `downstream_optimization=no` | 不触发本卡分叉 |

接口三问（传什么 / 什么口径 / 有多准）仍须执行，与本分叉同时成立。

---

## 衔接类型与规范

| 上游产出 | 下游角色 | 必须传递 | 下游必做 |
|---------|---------|---------|---------|
| 点预测值 | 需求/参数 | 预测值 + 预测区间 + horizon | 区间两端做情景（乐观/悲观）敏感性 |
| 分类概率 | 风险/状态 | 概率 + 阈值口径 + 校准情况 | 阈值扰动看决策变化 |
| 综合得分/排序 | 权重/优先级 | 得分 + 无量纲化与赋权口径 | 权重扰动稳健性（卡片 08） |
| 簇标签 | 分组策略单元 | 簇定义 + 判别规则（新样本可归簇） | 错分影响讨论 |
| 参数估计（弹性/系数） | 目标/约束系数 | 估计值 + 置信区间 | 参数在区间内扰动的灵敏度 |

---

## 关键规则（强制）

1. **口径一致**：上游产出的定义/单位/时间粒度在下游公式中原样使用；换算必须显式写出
2. **不确定性不落地成单点**：只把点预测塞进优化模型而不做扰动分析 = 验证缺失；至少对关键输入做 ±区间灵敏度
3. **可复算**：下游模型的每个外部输入都能在 solution.json / 论文中追溯到上游具体产出（哪个表/哪个模型/哪个参数）
4. **误差传播讨论**：上游误差对下游结论方向的翻转风险必须有一节/一段讨论
5. **模型族分叉**：按上表填写 `downstream_decision_kind` 并执行对应决策端；不得只完成上游预测/评价而把决策写成拍脑袋或再拟合

---

## 常见断裂点（红队高发）

| 断裂点 | 表现 | 处置 |
|--------|------|------|
| 时间粒度错位 | 月预测喂给日决策 | 显式分配规则 + 假设 |
| 样本范围错位 | 训练用 A 区域数据，决策用于 B 区域 | 外推声明 + 合理性论证 |
| 单位错位 | 千元/元、万吨/吨 | 单位核对进验证清单 |
| 区间被丢弃 | 只传点估计 | 补情景/灵敏度分析 |
| 预测未来不可得特征 | 用未来才知道的变量做输入预测（泄漏） | 特征可得性时点审查 |

---

## 验证清单

- [ ] 每个下游输入可追溯到上游具体产出？
- [ ] 口径（定义/单位/粒度/范围）一致性已逐项核对？
- [ ] 关键输入带不确定性且下游做了扰动/情景分析？
- [ ] 误差传播与结论翻转风险已讨论？
- [ ] 衔接关系已写入 feature_fingerprint 的 downstream_optimization、downstream_decision_kind 与 solution.json 对应字段？
- [ ] 结构化规划未用监督学习充当决策器？规则/阈值未误建成规划空壳？排队未改成回归「最优等待」？
