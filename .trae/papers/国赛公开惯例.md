## 一、方法学惯例（modeling-solver 重点遵循）

1. **蒙特卡洛仿真验证**：含随机性 / 不确定性 / 稳态假设的问题，必须使用蒙特卡洛仿真（≥1000 次，小样本时 ≥10000 次）对解析/枚举结果进行交叉验证。报告仿真次数、收敛情况（平均值的标准差）、与解析结果的偏差。若偏差 >5%，分析原因（如稳态假设不成立、独立性假设不成立）。**convergence 字段判定规范**（2020B 校准反馈，强化已有规则）：蒙特卡洛仿真 convergence 字段必须基于实际 std/mean 与预设阈值（如 5%）比较判定，禁止硬编码 'converged'。若 std/mean > 阈值，字段值应为 'not converged (std/mean=X% > Y% threshold)' 并在论文中明确报告未收敛状态及对结论的影响。判定逻辑示例：`if cv < threshold: 'converged (std/mean=X% < Y% threshold)' else: 'not converged (std/mean=X% > Y% threshold)'`。**不确定性参数登记-传播映射**（2015B 校准反馈 P-3，条件触发）：若读题阶段登记了不确定性/随机参数清单，模型验证阶段须给出映射表：每个登记参数 → 传播方式（独立抽样/合并入某扰动/固定不传播）+ 合并或固定的理由。合并处理导致覆盖缺口时，须在验证记录中显式声明。
2. **成本分层建模**：成本应分解为 ≥3 类独立类别（如采购 / 检测 / 装配 / 拆解 / 调换 / 运输 / 库存），每类单独建模、使用不同符号、独立呈现公式和经济含义，最后组合为总成本函数。
3. **贝叶斯方法备选**：参数不确定性分析除频率学派（Clopper-Pearson / Wilson）外，应讨论贝叶斯方法（共轭先验 Beta 分布）作为替代/补充，比较两种方法在小样本和大样本下的差异。
4. **动态规划适用性讨论**：具有多阶段结构（即使无显式时间维度）的问题，应讨论动态规划作为枚举法的替代方案，分析其状态定义、转移方程、复杂度优势（如从 O(2^n) 降至 O(n·|S|)），并说明为何选择/不选择 DP。
5. **策略转换临界点分析**：在灵敏度分析后，讨论关键参数（如次品率、成本）在何值时最优策略发生转换，绘制策略转换图（参数扫描下的最优策略分布）或表格，分析策略转换的经济含义。
6. **活跃约束标注**：在结果分析中标注各情形最优解处各约束的紧/松状态（active / slack），讨论放松紧约束能带来多少目标改善。**活跃约束附派生量数值**（2015B 校准反馈 P-1，条件触发：若 solution.json 报告 active_constraints）：若 solution.json 报告 active_constraints，则对每条被标注的约束同时由代码直接计算并写入最优解处的裕度或响应幅度数值（slack 量/边际响应/局部灵敏度之一，视约束类型而定），供下游直接引用；下游文档中涉及约束处效应的数值陈述必须引用该字段而非自行二次推导。
7. **design_critique 内部消化**（2026-08 批次 2026-08-C1，真实评阅反馈）：批判性讨论题目设计（约束是否完整？参数是否合理？假设是否需要放松？）属建模阶段内部防漏思考，产出必须**转化为显式假设与解读策略**落实到模型假设与问题分析节；**论文正文禁止以任何形式出现"题目设计合理性讨论"独立节或"建议在题目中……"类评点出题人表述**（评阅观感硬伤）。
8. **solution.json 字段命名准确性规范**（2020B 校准反馈，通用规则）：result_bundle/solution.json 字段命名必须准确反映数值含义，四类语义严格区分、禁止混用：上界（`*_upper_bound` / `perfect_information_upper_bound`，已知全部不确定性信息下的最优值）、期望值（`expected_*` / `*_expectation`，基于随机变量分布的期望）、代表性值（`representative_*` / `*_representative_scenario`，用某代表性场景求得的确定性最优值）、实际值（`actual_*` / `*_actual`，实际发生值）。禁止将上界命名为 expected_objective；若某字段含义可能歧义（如某策略不受随机因素影响导致期望=上界），须在字段注释或 modeling_plan.json 中明确说明"该策略下期望=上界，故字段值同时为两者"。每个易混淆字段附 `_note` 子字段说明数值来源与适用条件。
9. **枚举法完备性证明或截断依据**（2020B 校准反馈，条件触发：若使用枚举法求解）：若使用枚举法（如 BFS 路径枚举、策略枚举）求解优化问题，须在 modeling_plan.json 中证明枚举完备性（枚举了所有可行路径类型/策略类型，附策略空间规模与遍历依据）或说明截断依据（剪枝条件、复杂度上界、状态空间大小）。求解结果须与同类问题的已知最优解（若存在）对比验证，若差距 ≥5% 须分析根因。若求解数值低于已知最优解，根因方向为"约束违反导致虚假更优"（属不可行解，须修复约束实现后重求解）或"枚举遗漏"（属策略空间不完备，须补做缺失类型枚举）——两种根因方向相反，不得混淆。
10. **solution.json 字段值语义合理性判定**（自 agent prompt 迁入整合，原为 2020B/2021B 校准落地规则）：打包前对每个 solution.json 字段值做语义合理性判定——字段值是否符合其命名隐含的语义？（机查工具：`.trae/code_templates/check_solution_json.py`，打包前必跑，ERROR 阻塞打包）每字段附"字段名 → 字段值 → 语义合理性 → 判定（✓/✗）"四元组记录，任一 ✗ 当场修复 solution.json 或代码，禁止打包带病字段。典型判例：
    - `monte_carlo.convergence` 字段值必须与 std/mean 一致（不得出现 std/mean>5% 但字段值含 'converged' 的矛盾）；
    - 博弈类 `critical_points.*.deviation_obj` 必须 < 合作收益字段值（偏离收益 < 合作收益才能维持合作均衡，相等或大于均属逻辑错误）；
    - `active_constraints.X.min_observed` 必须取自全路径最小值（不得取初始值或局部极值冒充全路径最小值）；
    - `optimality.method` 字段描述与字段名必须一致（如 method 写 'Perfect information upper bound' 但 objective_value 命名 expected_objective，命名与描述矛盾）。
11. **题目原文核心参数逐字回读**（2023B 校准反馈，通用规则）：在 S1 反思门增加 P0 强制步骤"题目原文核心参数逐字回读"：将题目原文中所有数值参数（水深、尺寸、角度、阈值、边界条件等）逐字抄录至 modeling_plan.json 的 `source_parameters` 字段，并与 project/*.py 代码硬编码值逐项比对，任一不一致立即拦截并标记 BLOCKED，禁止带病进入 S2。回读记录写入 s1_reflection.md。
12. **几何方向语义判定**（2023B 校准反馈，条件触发：几何覆盖类问题）：若为几何覆盖类问题（题目含"等值线/梯度/方向"等几何方向描述），则建模阶段必须显式证明测线/路径方向选择（如"沿等值线方向"或"垂直于梯度方向"），并引用行业规范或数学证明作为支撑。证明结构含：命题陈述 + 证明过程 + 结论。证明内联正文，不得后置附录。方向选择记录写入 s2_reflection.md。
13. **指标量纲一致性核查**（2023B 校准反馈，通用规则）：P0 强制：题目要求计算的每个指标，必须在建模阶段对量纲与原义比对——字段名、单位、物理意义必须与题目原义逐字一致。若指标定义为长度量纲，禁止用百分比替代；若为百分比，禁止用长度替代；若为计数，禁止用比例替代。比对结果以"指标名 → 题目原义量纲 → 论文实际量纲 → 判定（✓/✗）"四元组记录写入 modeling_plan.json 的 `indicator_dimension_check` 字段。任一 ✗ 当场修复，禁止带病进入 paper-writer 阶段。
14. **灵敏度覆盖范围**（2023B 校准反馈，条件触发：含多个含优化的子问题）：若题目含多个含优化的子问题，则灵敏度分析必须覆盖每个含优化子问题的核心参数（不仅首个子问题），并绘制对应 Tornado 图或参数扫描表。每个含优化子问题至少对 1 个核心参数做 ±5%/10%/20% 扰动，识别最敏感参数与临界点。覆盖范围写入 s3_reflection.md 的 `sensitivity_coverage` 字段。
15. **控制方程完整性检查**（2019B 校准反馈 M-1，条件触发：力学/物理动力学建模类）：S1 隐含约束检查须额外包括"控制方程是否缺失物理反馈项"——如力矩方程中的几何反馈项（角度随时间变化）、运动方程中的非线性项（如科里奥利力、阻尼项）、能量方程中的耗散项。每条隐含约束须标注"是否影响数量级"。
16. **多模型候选对比的结构差异判据**（2019B 校准反馈 M-2/M-6，通用规则）：multi_model_candidates 字段必须对比 ≥2 种"控制方程/模型结构"差异，而非仅"求解算法/参数假设"差异——同一方程不同求解法（如解析 vs 数值积分）不算结构差异；不同方程结构（如无反馈方程 vs 含反馈项方程）算结构差异；不同参数化（如恒力持续 vs 瞬时冲量）不算结构差异。仅当问题本质为单一标准模型时可豁免，豁免须在 design_critique 写明理由。GQ4 中任何"简化忽略"标注（如"忽略二阶效应""忽略反馈项"）须触发至少 1 项"含 vs 不含该简化项"的数值差异对比，差异 ≥10% 须在 design_critique 讨论简化合理性。
17. **字段值间逻辑一致性核查**（2019B 校准反馈 M-4，通用规则）：solution.json 结论性字段须互相印证——best_strategy / recommended_strategy / objective_value 应指向同一策略；critical_points 描述应与 strategies_comparison / sensitivity_data 数据一致；active_constraints 标注应与 decision_variables 边界一致。每条核查附"字段名 A vs 字段名 B → 逻辑关系 → 判定（✓/✗）"四元组记录。本条同时适用于 decision_logs 各文件间关键数字（页数、评分、工单条数）的一致性抽查。
18. **论文算法描述与主代码实现一致性核查**（2019B 校准反馈 M-5，通用规则）：论文描述的算法步骤（如多起点验证、收敛性检查、迭代次数、随机种子）必须在主代码（非辅助脚本）中实现——论文描述"N 起点验证"→ 主代码须有 N 起点循环；论文描述"迭代次数 K"→ 主代码须有 K 次迭代逻辑；论文描述"随机种子 S"→ 主代码须使用种子 S。
19. **反直觉结论交叉验证**（2019B 校准反馈 A-1，通用规则）：若论文报告反直觉结论（与直觉或常识相反的结论，如"增大某参数反而降低目标值"），核查项：(a) 是否用至少一种与原方法原理不同的独立方法（解析推导/数值仿真/物理直觉/对照实验）交叉验证；(b) 是否讨论结论对模型假设的依赖性；(c) 若未交叉验证且未讨论依赖性，标为 high severity 要求修复。（**本条为唯一完整定义，reviewer prompt 必查清单 #9 与本条同源，修订须同步**）
20. **求解结果量级合理性核查**（2019B 校准反馈 A-2/M-3，通用规则）：若求解结果数值量级与可对照的同类问题参考结果差异显著（如 >10 倍），须显式讨论根因；无同类参考时须讨论结果的物理/业务/常识合理性（物理量示例：力是否在人体工程学范围、角度是否物理可实现、能量是否不超系统总量）。未讨论则标为 high severity 要求修复。（**本条为唯一完整定义，含物理量示例；reviewer prompt 必查清单 #10 为本条简写同源，修订须同步**）
21. **LP 包装函数接口一致性**（条件触发：若用 LP 包装函数）：所有 LP 包装函数必须完整返回全部决策变量值（含辅助变量）并正确回写结果字典；返回值缺失/回写错误属接口 bug，须原文件修复接口，禁止绕过或以其他子问题结果复用。
22. **检索来源管理核查**（2015B 校准反馈，通用规则）：(a) 时间口径——若引用外部数据来源（非题目附件给定），其发布时间不得晚于赛题发布日期；参考文献发表年份不得晚于赛题发布日期。晚于者属时代错位，须替换为赛题日期前的等价来源；无法替换时删除该来源并改用其他锚定方式。训练模式演练往年题同样适用（模拟真实比赛信息环境）。(b) 完整性——正文括注的数据来源（报道/统计/数据库/平台披露）必须全部进入参考文献列表或附完整出处，禁止只在正文括注而无列表条目。

## 二、写作惯例（paper-writer 重点遵循）

1. **附录含可运行代码**：附录含至少 1 段实际可运行代码（Python/R），不仅仅是伪代码。**附录代码中文处理强化**（2023B 校准反馈，强化已有规则）：在原条款基础上追加：附录代码必须保留中文注释、docstring、变量名；**禁止使用 listings 排代码**（丢中文注释），统一用 fvextra + \VerbatimInput 直接引用 .py 源文件（见 LaTeX格式规范 §一）；禁止以"技术限制""环境兼容性"为由丢失代码注释字符。附录代码必须与 project/*.py 实际代码逐行一致（含中文注释、docstring、变量名）。s4 反思门逐行核对，相似度 <95% 即标记 ✗。
2. **图表含算法流程图**：图表类型中含算法流程图 ≥1 张。
3. **参考文献可查证**：参考文献可查证（WebSearch 能找到 DOI 或出版社页面，链接可达）且发表年份不晚于赛题发布日期；正文括注来源全量入列（见一.检索来源管理核查）。
4. **符号跨节一致性**：同一符号在参数表 / 公式 / 附录 / 图表四处含义必须一致，禁止同名异义。
5. **量纲一致性**：同一物理量的量纲全文统一（如元/件 vs 元/时间不可混用），若有多等价形式必须标注转换关系。
6. **附录推导完整性**：对所有分段函数，必须对每种情形从第一原理推导，展示成本流向（收入项 / 成本项 / 回收项），禁止"详细推导较为复杂"类回避性表述。
7. **手算代码验证**：附录手算推导完成后，必须用代码重新计算验证，数值一致方可写入论文；正文表格、附录手算、solution.json 三方数值必须一致。
8. **数值 source 核查**：论文中所有数值（含临界点、参数范围）必须有 solution.json 或图表数据支撑，禁止凭直觉给出。**派生数值显式覆盖**（2015B 校准反馈，强化已有规则）：数值 source 核查须显式覆盖"论证句派生数值"——由模型输出二次推导的正文量级表述（形如"提升最高约 X%""降低近半""X 倍于"等），该类数值无 solution.json 字段直引，必须当场用模型参数与代码重算验证；重算口径（基准参数/区间上界）须与语句的确定性陈述口径一致。
9. **无目录、摘要页三件套**：论文不设目录（官方明确"不要目录"）；摘要页只含标题+摘要+关键词，不出现队名/日期（不使用 `\maketitle` 默认信息）。
10. **主体按问题组织**：模型建立与求解合一，按问题分节，每个问题内部完成 建立→求解→验证→结果分析；推导内联正文，不得后置附录（附录仅放源程序代码、支撑材料列表、确实过长的补充推导）；附录代码必须与 project/ 实际代码一致，禁止示意性改写。
11. **摘要按问题分段**：首段 1-3 句背景+总体思路，随后每问一段（方法+算法+定量结论）；关键词 3-5 个。**摘要条件数值限定词保留**（2015B 校准反馈 W-2，条件触发：摘要引用数值在正文中为条件依赖量时）：摘要引用的数值若在正文中为条件依赖量（基准参数情形 / 特定场景 / 参数区间特定端点），摘要须保留最简条件限定词（如"基准情形下"）；检查方法为摘要数值与正文同数值出现处逐一对照，条件限定词丢失即判 ✗。
12. **假设简明、符号单表**（2026-08 批次 2026-08-C1 收紧，真实评阅反馈）：模型假设 3-6 条、**每条为纯断言句**——需说明理由/放宽影响的解释性内容（"该假设是题目隐含条件""放宽可引入……"类跟句）必须归位问题分析或灵敏度分析节，禁止附在假设条目后；符号说明默认单表（符号/说明/单位），优化类符号较多时可分"决策变量/参数"两表；说明须准确具体。
13. **数据探索进正文**（条件触发：数据驱动/统计类问题）：散点图/分布观察→初步规律→异常点识别与处理，作为模型建立的第一步写进正文对应问题小节。
14. **修复回路后 JSON 三方一致性回读**（2020B 校准反馈，通用规则）：修复回路（R1/R2/R3）完成后，paper-writer 须回读 result_bundle/solution.json，核对所有论文表格中引用的数值字段与 JSON 字段值、代码实际计算值三方一致。若 JSON 字段值与论文修复后不一致，须同步修正 JSON（修打包脚本或对应求解脚本后重新打包）或在论文中显式说明 JSON 字段未同步的原因与计划。**禁止仅修复论文层面而留 JSON 字段不一致**——评审与校准会以 JSON 为基准核查论文，未同步将判为一致性缺陷。
15. **正文超 30 页压缩预案**（2020B 校准反馈，强化已有规则，通用规则）：正文超 30 页宽松上限时，paper-writer 须触发压缩预案：(1) 合并同类节（如共用框架的多个子问题求解过程）；(2) 精简模型评价节（优势/局限/改进/讨论各 ≤3 条）；(3) 表格合并（信息重叠的表格整合为多面板表）；(4) 算法流程图与代码段精简（流程图保留核心步骤，删除冗余分支描述）。**禁止以任何形式缩减附录完整可运行源程序**——附录代码缺一取消评奖资格（官方硬约束），压缩只作用于正文。压缩后仍超 30 页须报告用户作最终决断。
16. **去 AI 味写作规则**（一处定义，细则承载于《去AI味写作规范.md》，垂直优化自 Humanizer-zh / blader-humanizer 的 24 种 AI 模式检测规则）：写作阶段按规范文件从源头控制 AI 痕迹，阶段 5 自审以规范文件黑名单为准逐项核查（含禁用词/禁用句型/数模特有模式/真实感注入/标点规范/机查化条款与快速自查清单）。规范文件的"内部高频短语与超长段落"（原二.16b）机查化不变，check_latex_compliance.py 检查 7/12 引用继续有效。
17. **论文-JSON 引用契约**（自 paper-writer prompt 迁入，原为 2020B/2021B 校准落地规则）：(a) **枚举型字段逐字引用**——solution.json 中枚举型字段（如 strategy_names、action_sequence、convergence、optimality.method 等字符串列表/标识字段）在论文中引用时必须逐字一致，禁止改写、缩写或意译（如字段值 `['strategy_A', 'strategy_B']` 不得改写为"先执行策略A再执行策略B"），保证代码-论文可追溯性；(b) **字段名 vs 文字解释对照**——论文正文文字解释数值时必须能追溯到 solution.json 具体字段名（如 `q2.active_constraints.money_nonneg.min_observed`），禁止论文表述与 JSON 字段名脱节；每条文字解释附"JSON 字段路径 → 字段值 → 论文表述"三元组。
18. **多目标处理透明度**（2023B 校准反馈，条件触发：多目标优化问题）：若为多目标优化问题（题目含"尽量"+多个冲突目标，或显式多目标），则论文必须：(1) 明确论证主目标选择依据（如"为何覆盖率优先而非长度优先"），引用题目语义或工程实践作为支撑；(2) 讨论替代方案（Pareto 前沿含义或权重来源）；(3) 透明披露约束违反情况（如某指标未达阈值）；(4) 给出主目标法/加权法/NSGA-II 等候选对比。禁止仅写"采用主目标法"而不论证选择依据。
19. **B 题论文写作图表清单预审 B 题特殊核查可视化对照列**（2019B 校准反馈，W-3，条件触发：B 题论文写作）：若为 B 题论文写作，handoff_notes_2.md 图表清单预审表格增加"B 题特殊核查对应图表"列，逐条核查 B 题特殊核查项（#2 收敛性/最优性可视化、#3 Tornado 灵敏度图、#4 活跃约束标注、#6 术语表五类分类等）对应的图表编号或章节位置；任一项无对应产物 → 预审不通过。
20. **S4 红队几何/物理退化条件严格性论证**（2019B 校准反馈，W-6，条件触发：约束矩阵奇异性/几何退化/边界条件/物理退化）：若论文涉及约束矩阵奇异性/几何退化/边界条件/物理退化，红队须独立核查几何/物理退化条件的严格性论证（如"完全奇异"vs"条件数显著增大但非无穷"），避免定性描述替代严格论证。

25. **核心公式反算验证**（通用规则）：随机选取 ≥2 个核心公式（不含已用代码复算验证的手算数值），从建模假设出发手工反算一遍（代数变形/量纲分析/特例代入等独立路径），检查是否有跳跃或错误；不一致 → 当场修正并标注根因。反算记录写入 s4_reflection.md（"公式编号 → 反算路径 → 反算结果 vs 原结果 → 判定"）。

27. **摘要蒙特卡洛偏差注脚**（条件触发：若含蒙特卡洛仿真且偏差 >5%）：摘要引用的"上界/代表性最优值"必须配偏差注脚（格式："数值 X（蒙特卡洛期望 Y，偏差 Z%，作上界参考）"），禁止只报上界不报偏差。

30. **模型→算法映射推导**（通用规则）：模型求解处的算法选择理由必须基于"模型结构特征→算法适用性"的映射推导——显式写出模型的凸性 / 线性 / 整数性 / 组合结构 / 问题规模等结构特征，据此论证所选算法为何适用；论据须取自 `decision_logs/method_card_matching.md` 的命中卡片理由（适用条件核对 + 候选提取）。禁止"全局搜索能力强""简单高效""鲁棒性好"等脱离模型结构的空泛理由。
31. **多模型视角对比取舍**（条件触发：modeling_plan.json 含 multi_model_candidates 即 ≥2 种独立建模视角）：须在模型建立处将各独立视角落为正文对比，并给出"为何选此弃彼"的取舍理由（结构差异 / 求解代价 / 假设一致性）；禁止仅记录于内部决策日志而不在正文呈现，使建模阶段的多视角成果在论文中无处安放。
32. **符号就近身份重申**（2026-08 批次 2026-08-C1，真实评阅反馈，通用规则）：符号说明表是索引而非读者唯一取义途径（评阅人不会回翻查表）——每个核心符号在正文每节（或每个子问题小节）首次出现处，用"中文身份（符号）"或"符号（中文身份）"形式就地标注；重要参数跨节重现时重申简述身份（如"次品率 $p_0$"而非裸 "$p_0$"）；摘要中出现的符号一律就地带身份。
33. **摘要关键词行加粗**（2026-08 批次 2026-08-C1，真实评阅反馈）：摘要关键词行的关键词词汇统一加粗（`\textbf{...}`），标签"关键词："保持既有黑体样式；不得以此为名对摘要正文其他部分额外加粗。
34. **正文符号单表、术语细节入附录**（2026-08 批次 2026-08-C1，真实评阅反馈）：正文符号说明节统一为一张表（符号/说明/单位，可按决策变量/参数分组），算法术语等细节类表移入附录（如"术语补充说明"节），正文在该处指明附录位置；禁止在正文符号说明节罗列多张细节表占用篇幅。

## 三、评审惯例（independent-reviewer 重点遵循）

1. **模型验证 vs 最优性验证区分**：求解验证维度应拆分为"最优性验证（MIPGap / 枚举完备性 / 迭代收敛曲线）"和"模型验证（蒙特卡洛仿真）"两个子项，两者不可相互替代。
2. **跨节符号一致性核查**：每轮评审必须对每个核心符号，对比参数表 / 公式 / 附录 / 图表四处含义是否一致。
3. **量纲一致性核查**：目标函数的量纲必须全文统一。
4. **代码-论文一致性核查**：核查论文公式符号与代码变量名的含义、数值是否一致。
5. **数值 source 核查**：论文中所有数值（含临界点、参数范围）必须在 solution.json 或图表中找到 source，否则扣诚信分。**派生数值显式覆盖**（2015B 校准反馈，强化已有规则）：数值 source 核查须显式覆盖"论证句派生数值"——由模型输出二次推导的正文量级表述（形如"提升最高约 X%""降低近半""X 倍于"等），该类数值无 solution.json 字段直引，必须当场用模型参数与代码重算验证；重算口径（基准参数/区间上界）须与语句的确定性陈述口径一致。
6. **图表逐图核对**：逐图核对每张图是否符合 prompt 的具体类型分配（如 fig5 必须是 Tornado 图）。
7. **凑数图识别**：识别信息密度低、与核心论点关系弱的凑数图，每张扣 1 分。
8. **红队思维**：评审必须假设自己是红队做对抗性搜查（目标：若不修复则论文结论不可信或方法学有根本错误的问题）；不设问题数配额，搜查范围与证据按 rules "红队自查机制"节执行（一处定义）。
9. **全文通读**：无论第几轮评审，均需全文通读 + 跨节核查，禁止"基于上轮反馈的增量评审"模式。
10. **摘要定稿审计门**（2026-08 批次 2026-08-C2，真实评阅反馈）：评审轮对摘要执行审计门——按 `.trae/papers/摘要写作规范.md`（一处定义）执行信息损失六型识别、S/A/B/C 分级与数字评委判断门，审计证据写入 review_report.json 摘要审计字段；损失六型任一中标即生成摘要修复工单（severity 按信息损失程度定），paper-writer 修复后 review 须核对摘要正文边界外内容逐字符未变（`check_abstract_guard.py verify`）。

## 四、校准惯例（calibration-analyzer 重点遵循）

1. **双维度校准**：既做"方法学对标"（AI 论文 vs 国赛论文），又做"论文内部质量审计"（AI 论文内部自洽性）。
2. **读取代码和 solution.json**：校准必须读取 AI 论文的 project/*.py 和 result_bundle/solution.json，做"代码-论文-solution.json 三方一致性核查"。
3. **红队自查**：对执行层做对抗性搜查（目标：符号 / 数值 / 形式 / source / 代码-论文一致性差距）；不设问题数配额，搜查范围与证据按 rules "红队自查机制"节执行（一处定义）。
4. **校准反馈闭环**：每题校准完成后，将"通用规则"gap 脱敏为"通用方法学建议"，反馈给对应 agent 的 prompt，下一题主动避免同类问题。
5. **论文附录代码与实际代码一致性**（@paper-writer，2021B 校准反馈）：论文附录代码必须与 project/*.py 实际代码逐行一致（含变量名、运算式、公式符号）。禁止"两套代码"——附录代码为展示版，实际代码为运行版。paper-writer 产出的论文附录代码必须从 project/*.py 实际代码复制，不得手写简化。
6. **数值指标三方一致性核查**（@paper-writer，2021B 校准反馈）：对易混淆的数值指标（如 SEM/mean vs std/mean、绝对偏差 vs 相对偏差、pp vs %），论文正文、附录代码、solution.json 三方含义与数值必须一致。指标定义若涉及相似但不同的概念（如收敛比 SEM/mean 与变异系数 CV=std/mean），必须在论文中明确区分。
7. **蒙特卡洛仿真描述与实现一致性**（@modeling-solver，条件触发，2021B 校准反馈）：若题目含随机性/不确定性，蒙特卡洛仿真论文描述（加噪方式：输入加噪/输出加噪/中间加噪；噪声分布；随机种子；采样次数）必须与 project/*.py 实际实现一致。禁止论文描述"输入加噪"但代码实现"输出加噪"。
8. **handoff_notes 实测值与原始数据比对**（@modeling-solver，2021B 校准反馈）：handoff_notes 中引用的实测值（如某组合在某温度下的转化率/收率）必须与附件原始数据一致，禁止凭记忆写入。modeling-solver 产出 handoff_notes 时必须从附件数据现读现写。
9. **clip/截断操作完整报告**（@paper-writer + @modeling-solver，条件触发，2021B 校准反馈）：若代码含 clip/截断操作（如 np.clip(X, 0, 100)），必须在论文中完整报告：截断位置、截断阈值、触发次数、对结论的影响。禁止代码含截断但论文未报告。
10. **修复回路 R1 失败率监控**（@independent-reviewer，2022B 校准反馈）：R1 复审时统计"修复引发跨节新错数 / 已修复项数"的失败率。若失败率 ≥30%，在 `decision_logs/review_report.json` 标注 `fix_failure_rate_warning: true` 字段，并在 `handoff_notes_3.md` 提示 paper-writer 强化全局扫描机制（**本条为唯一完整定义，reviewer prompt 复审协议第 2 条与本条同源，修订须同步**）。
11. **参照论文完整度分级响应机制**（C-01）：按 OCR 完整度分三级——A 级（完整正文 ≥80%）：方法学对标作严谨分值评估，步骤 2a 标"严谨分值"；B 级（50-80%）：部分章节缺失但摘要+方法+结果可提取，方法学对标作"方向性参考，非严谨分值"，须在 calibration_report 摘要显式声明，步骤 2a 标"方向性参考"；C 级（<50%）：仅摘要或结构元信息可获取，方法学对标仅作"结构合规性对比"，禁止作方法学分值评估，步骤 2a 标"结构层 only"，同时建议由具备视觉能力的通道补做。分级判定须附 OCR 完整度估算依据。
12. **维度零"方法学专有术语"判定边界**（C-03）：区分两类术语——同题特定方法组合（含污染：某题独创的方法组合，含特定算法+特定数据维度+特定创新点，必须脱敏或转修复工单）；跨题通用方法名（不含污染：学科内有独立定义且跨题可用的单一通用方法学名称，即使本题为首次应用也不视为污染）。争议情形默认按"跨题通用方法名"处理，但在审批清单中标注"[边界判定] 待用户确认"。
13. **维度零检查范围扩展**（C-1）：除规则提案文本外，须检查校准产出物（calibration_report.md / calibration_log.md / 审批清单.md / 维度零检查记录 / fix_round3.md 等）中作为分析证据的参照论文具体数值是否必要。必要的对比分析证据可保留，但须在产出物开头声明"本文件含同题参考论文具体数值，仅 @calibration-analyzer 与主智能体可读，其他 agent 不得读取"。参照论文 PDF 的文本提取物须保存到独立隔离目录（如 decision_logs/_isolated_refs/），校准完成后由主智能体归档或删除。复盘阶段由本智能体核查产出物读取情况（通过其他 agent retro_*.md 的"信息隔离声明"反向核查）。**校准产出物分层可读**（2015B 校准反馈 RC-1）：校准产出物（calibration_report.md / calibration_log.md）实行分层标注——含参照论文具体数值、方法明细的节标注"【隔离节】仅 @calibration-analyzer 与主智能体可读"；差距编号、脱敏后的差距描述、C-04 协同统计、修复工单与验证结果、审批清单（脱敏版条款文本）归为"【可共享节】"，供其他 agent 复盘阶段按需引用。整文件级 C-1 声明相应细化为节级声明。若无法分节隔离，维持整文件隔离并由主智能体向其他 agent 转述可共享内容。
14. **"强化执行"机制落地校验**（C-05）：审批清单标注"已有规则，强化执行"时，须记录三元组——强化前条款（文件路径+条款编号+原文文本）；强化后条款（标注新增/修改的具体内容）；强化理由（本次强化的根因）。审批通过后由本智能体回读对应共享文件，核对强化后条款与脱敏版逐字一致；有出入立即报告主智能体修正。强化记录写入 calibration_log.md 步骤 6 节，每条附"强化前 → 强化后 → 落地校验结果"三元组。
15. **R3 修复工单字段集/字段值一致性协议**（C-4）：R3 修复后 solution.json 须满足"字段值一致性"（已有字段值与 R1 修复后一致）+ "字段集非破坏性"（不删除已有字段，可新增字段但须在修复日志中说明新增字段名与用途）。验收标准区分"字段值核查"（逐字段一致）与"字段集核查"（记录新增字段并说明合理性）。fix_round3.md 模板新增"字段集变更声明"子节，由 @paper-writer 在执行 R3 时填写。**R3 工单与修复日志两项加固**（2015B 校准反馈 RC-3）：(a) 若 R3 工单涉及文献/来源/条目类修复，验收标准必须含"双向核对"——列表无闲置条目（每条均在正文有实质引用位置）、正文无缺失条目（每处括注均可回溯至列表条目或完整出处）、无"某研究"类模糊指代；(b) 修复日志（fix_round{N}.md）须含"超范围保留项说明"子节——修复范围外文件中的历史痕迹（过程日志、数据环境描述、冲突取舍论证的对立侧记录）不得修改，须逐项声明保留位置与理由（保护复盘证据链）。
16. **C-04 协同漏报率指标**（C-5）：漏报为双向定义——reviewer→calibration 漏报（reviewer 初审未发现但校准发现的差距数）/ calibration→reviewer 漏报（校准未发现但 reviewer 红队清单已提的差距数）。漏报率：reviewer 漏报率 = reviewer→calibration 漏报数 / (reviewer 初审发现数 + reviewer→calibration 漏报数)；calibration 漏报率同理。漏报率 >30% 须在校准报告中分析根因（如本智能体审计覆盖不足 / reviewer 红队范围受限）。
17. **方法学创新点可移植性评估**（C-3）：步骤 2a 方法学对标时，对每条参照论文核心创新点评估其跨题可移植性——是否跨题通用方法（如蒙特卡洛仿真、动态规划）→ 可作为通用规则候选 / 是否题型特定方法（如特定几何建模法）→ 仅作对比依据不进入共享文件。评估结果记入 calibration_log.md 步骤 2a，作为维度零"方法学专有术语判定边界"的辅助证据。

## 五、机查裁定（全 agent 通用）

1. **机查 WARN 裁定权条款**（2023B 校准反馈，通用规则）：机查工具（check_solution_json.py / check_latex_compliance.py 及后续同类工具）报出的 WARN，产出方（生成被检产物的 agent）不得单方裁定为"虚惊/可接受"：产出方可给出初判意见，但最终裁定由下一阶段独立 agent（reviewer 或 calibration-analyzer）作出并记录理由。其中**附录代码一致性类 WARN 默认按真问题处理**（须修复或改用 \VerbatimInput 直引源文件），仅当能提供逐行比对证据证明"仅注释/空行差异"时才可降级。
2. **机查要求集与 prompt 要求集同步**（2019B 校准反馈，T-1，通用规则）：新增或修改机查项时，须同步核对对应 agent prompt 是否已下达该要求：机查要求集不得超出 prompt 要求集。若机查项检查的要求未在 prompt（或其指针指向的外部规范文件）中声明，须先补 prompt 要求/指针，或将该机查项降级为 INFO；否则该机查项产出的 WARN 将被合规裁定为 PASS，检查失效。机查工具的每次修改须在 commit message 中记录各检查项对应的 prompt 条款位置。

## 七、更新机制

- 每题校准完成后，若有新的"通用规则"gap，由 @calibration-analyzer 追加到此文件。
- 追加前需脱敏：去除同题特定信息（具体方法名、公式、符号、数据），保留跨题通用的方法学建议。
- 追加格式：`N. **建议名称**：具体要求描述`
- 追加规则需标注反馈来源题号（如"2021B 校准反馈"），便于追溯改进效果。
- 追加规则时同步检查与既有规则是否重复/冲突，可合并的合并，低频/已内化的归档（防 prompt 膨胀）。
- **条目变更须同步文首目录**：追加/合并/归档任一条目后，同步更新文首「条款锚点目录」的编号与标题；机查 `check_convention_refs.py` 对账目录声明与正文实际编号，不一致判 ERROR。新条目仅允许**节末追加**（禁止中间插入引起编号漂移，已有编号引用会失效）。
