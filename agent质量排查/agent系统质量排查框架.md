# Agent 系统质量排查框架

> 用途：作为「数模 B 题智能体流水线系统」全方位质量排查的板块划分骨架。
> 后续与 agent 质量排查相关的工作文件、排查记录、问题清单均统一放入本目录（`agent质量排查/`）。
> 本框架只做「划分」，不判「对错」；每板块的具体检查项、判据、问题记录另起文件。

---

## 一、划分原则

1. **架构分层**：按「控制面 → 业务能力面 → 支撑面」三层组织，对应典型 Agent 系统
   的 Orchestration / Core Capabilities / Foundation 结构。
2. **全链路覆盖**：从 HG0 准入（输入）→ 求解 → 写作 → 评审 → 校准 → 复盘（输出）逐段闭合，
   不遗漏任一环节。
3. **可独立评估**：每个板块有明确的「功能边界 + 关键子模块 + 对应资产文件」，可单独定位问题。
4. **核心能力映射**：4 个 subagent 各占一个业务板块，编排器占控制板块，机查/知识/隔离占支撑板块。

## 三、各板块详解

### 板块 1｜编排调度（Orchestration & Control）
- **功能边界**：不产出专业内容，只做流程控制——状态机转移、门控放行/退回、子任务派发、重试与回退、复盘组织。
- **关键子模块**：
  - 比赛/训练双状态机（`HG0→…→DELIVERED` / `HG0→…→DONE`）
  - HG0-HG3 四道门控 + 退回协议（RETREAT）
  - BLOCKED 回退协议、重试 ≤2 次
  - 并行兼容性矩阵（约束 subagent 并行时机）
  - 复盘四任务并发组织
- **对应资产**：`.trae/rules/orchestrator.md`

### 板块 2｜状态与可观测（State & Observability）
- **功能边界**：状态记录与决策留痕的唯一载体，供断点接管、耗时统计、复盘追责。
- **关键子模块**：
  - `pipeline_state.json`（current_stage / stage_timestamps / machine_checks / blocked_history）
  - `decision_logs/`（5 份反思日志 + fix_round + retro_* + retrospective）
  - 断点接管协议、subagent 上下文接力
- **对应资产**：pipeline_state 契约（orchestrator §3）

### 板块 3｜准入与上下文（Intake & Context）
- **功能边界**：流水线入口——题型判定、三要素声明、赛题与附件接入、特征指纹生成。
- **关键子模块**：
  - HG0 题型判定（优化题走全路径 / 非优化题 fallback）
  - 运行模式 / 项目根 / 参考论文路径声明
  - 附件数据质量检查（>1000 行禁全量读）
  - `feature_fingerprint.json` 特征指纹
- **对应资产**：AGENTS.md「运行模式」「编排顺序」节

### 板块 4｜建模求解（Modeling & Solving）
- **功能边界**：核心求解能力——读题→优化建模→算法选择→编程求解→灵敏度→验证→打包 result_bundle。
- **关键子模块**：
  - GQ1-GQ5 引导问题链
  - S1/S2/S3 三道反思门（完整性/对抗深挖/红队）
  - 求解后端（MIP/CP-SAT/图/NLP/元启发式/MC）
  - 最优性验证 + 模型验证（蒙特卡洛）+ 灵敏度
  - 可视化规范（对接 figure-studio）
- **对应资产**：`.trae/agents/modeling-solver.md`、`.trae/code_templates/solver_backend.py` 等求解模板

### 板块 5｜论文写作（Writing）
- **功能边界**：把 result_bundle 转成合规论文——LaTeX 写作→编译 PDF→自审→接收评审反馈执行修复。
- **关键子模块**：
  - 摘要四要素 + 一页约束、符号术语一致性
  - 图表分配与 `\ref{}` 引用、图表 ≥6
  - S4 反思门 + 自审
  - R1-R2 修复回路执行（含图面级修复授权）
- **对应资产**：`.trae/agents/paper-writer.md`

### 板块 6｜质量评审（Review）
- **功能边界**：独立盲审——五维度评分 + B 题 12 项核查 + 红队举证 + 复审验证修复。
- **关键子模块**：
  - 五维度评分（附 ≥3 句依据）、B 题 12 项核查
  - 红队努力举证制（含虚惊标注，禁凑数）
  - `review_report.json` + `review_scores.md`
  - 复审全文通读 + 修复点全节数值重算
- **对应资产**：`.trae/agents/independent-reviewer.md`

### 板块 7｜校准进化（Calibration & Evolution）
- **功能边界**：唯一接触获奖论文的板块——对标定差距→通用性审计→产出审批清单与修复工单→复盘进化。
- **关键子模块**：
  - 维度零（同题污染）检查
  - 差距分析（≥3 条，每条附三维度通用性判决）
  - 执行层修复工单（fix_order，R3）
  - retrospective 复盘产物
- **对应资产**：`.trae/agents/calibration-analyzer.md`

### 板块 8｜知识底座（Knowledge & Rules）
- **功能边界**：跨 run 复用的静态资产——规则、惯例、方法卡片、代码模板、图表规范。
- **关键子模块**：
  - `.trae/papers/`（国赛惯例、产物注册表、图表参考库、LaTeX 规范…）
  - `.trae/references/`（经典模式库）
  - `.trae/papers/优化方法卡片/`（12 张）
  - `.trae/code_templates/`（求解模板、样式模板、检查模板）
- **对应资产**：`.trae/papers/`、`.trae/references/`、`.trae/code_templates/`

### 板块 9｜工具与机查（Tools & Machine Checks）
- **功能边界**：把「质量规则」编译成可执行代码，零注意力成本守卫——机查脚本 + 出图/引文工作流 skill。
- **关键子模块**：
  - `check_*.py` 机查脚本（solution_json / modeling_artifacts / latex_compliance / isolation / prompt_budget / viz_tests…）
  - `figure-studio`（出图 7 步工作流 + 配方）
  - `reference-studio`（引文双向核对 + 可达性审计）
- **对应资产**：`.trae/code_templates/check_*.py`、`.trae/skills/`

### 板块 10｜隔离与安全（Isolation & Safety）
- **功能边界**：贯穿全程的护栏——信息隔离、防过拟合、泄漏审计、匿名合规。
- **关键子模块**：
  - 参考论文白名单/黑名单（`_quarantine/` 强制入目录）
  - `check_isolation.py` 泄漏审计（含签名规程）
  - 防过拟合 8 条铁律（维度零/条件触发/通用性判决/commit 绑定…）
  - 合规检查（匿名性/摘要单页/附录源码/参考文献可查证）
- **对应资产**：AGENTS.md「信息隔离」「防过拟合铁律」「合规检查」节

## 四、用于排查时的边界校验

一个质量问题可先按「层」定位，再按「板块」精确定责：

| 问题信号 | 首选排查板块 |
|---------|-------------|
| 状态机乱跳 / 门控漏拦 | 板块 1 编排调度 |
| 状态与实际产物漂移 | 板块 2 状态可观测 |
| 题型判错 / 数据读错 | 板块 3 准入与上下文 |
| 模型错误 / 验证缺失 | 板块 4 建模求解 |
| 排版/页数/自审遗漏 | 板块 5 论文写作 |
| 评分失真 / 红队凑数 | 板块 6 质量评审 |
| 规则过拟合 / 同题污染 | 板块 7 校准进化（+ 板块 10） |
| 规则互相矛盾 / 模板滞后 | 板块 8 知识底座 |
| 机查失效 / 配方 API 脱节 | 板块 9 工具与机查 |
| 参考论文泄漏 / 匿名信息 | 板块 10 隔离与安全 |

## 五、本目录约定

- 本目录（`agent质量排查/`）集中存放 agent 系统质量排查相关的工作文件与记录。
- 建议文件组织：
  - `agent系统质量排查框架.md`（本文件，板块划分骨架）
  - `板块N_<板块名>_排查记录.md`（各板块的排查检查项、判据、问题清单）
  - `问题汇总与跟踪.md`（跨板块问题汇总、优先级、处理状态）
- 每个排查记录文件建议固定含四段：**检查项 / 判据 / 发现问题 / 处理建议**，便于回溯与闭环。
