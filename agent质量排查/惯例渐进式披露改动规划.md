## 三、方案设计

### 3.1 索引结构（三层）

```
## 索引（渐进式披露导航；机查对账对象，与正文同步维护）
### 一、方法学惯例 ｜ 职责方：modeling-solver（必读） ｜ 条目 1.1–1.26
| 编号 | 标题 | 触发 |
| 一.1 | 收敛判定与不确定性参数登记-传播映射 | 条件 |
| ...（条目级清单） |

### 二、写作惯例 ｜ 职责方：paper-writer（必读） ｜ 条目 2.1–2.31
...
```

要点：
- **条目级清单**（编号+标题一句话）：agent 用标题 Grep 正文定位，正文**不需要**加编号锚点（正文条目无"二.16"前缀，Grep "二.16"会失败——标题检索绕开此坑）
- 「必读」标注职责条目（本角色无条件精读），其余为"引用触发式"条目
- 索引允许每节开头有一段 ≤3 行节概要

### 3.2 检索协议（写入 4 个 agent 的共性条款）

> 惯例读取协议（一处定义，各 agent 前置读取处指针）：
> ① 先读惯例文首索引，定位本职责条目清单；
> ② 职责条目：动笔相关阶段前精读全文；
> ③ 引用式条目：遇"按惯例 X.Y 执行"时，用 Grep 搜标题定位该条目后精读该条，禁止凭索引标题概要执行；
> ④ 检索失败（标题无命中）：不得跳过该检查，须在对应日志中显式记录"条目 X.Y 检索失败"并向上游声明。

### 3.3 机查（I-1 升级：惯例编号引用完整性 + 索引对账）

`check_convention_refs.py`（仿 check_card_refs）：
1. 扫描全系统 md/py 中「惯例 X.Y」引用 → 与惯例正文实际条目编号比对 → 悬空 ERROR
2. 索引声明的「节条目范围」与正文实际编号对账 → 不一致 ERROR
3. 输出终端 + 登记 orchestrator §4「共享文件落地后」组
