# 摘要写作规范（国一摘要语义蒸馏 · 跨题通用）

> 本文件提炼自历年国赛一等奖摘要逐篇语义阅读后蒸馏出的**写作决策知识**（来源仅含跨题写作决策，不含范文原文、题号、专有符号与同题数据，不违反信息隔离铁律）。
> 生效环节：**评审定稿环节**（independent-reviewer 摘要专项审计门，一处定义）；paper-writer 在修复回路摘要定稿时按本文件执行。

## 一、审计范式（核心，非润色器）

摘要审计不是逐句润色，而是：**通读正文 → 逐问建带证据定位的信息候选池 → S/A/B/C 价值分级 → 基于正文重新成文 → 反向事实审计**。原摘要只是待核查线索，不限制重构幅度；新增的模型、数值、检验必须有正文直接证据。

## 二、信息损失六型（审计门必查）

| # | 类型 | 判定 | 处置 |
|---|------|------|------|
| 1 | 有模型没结果 | 只说采用某模型/算法，未说明得到什么 | 回正文结果节提取该问最终答案 |
| 2 | 有结果没数值 | 正文有准确率/成本/最优值，摘要只写"效果较好" | 选最能证明答案的数字替换空泛评价 |
| 3 | 有创新没体现 | 正文有瓶颈—设计—效果证据链，摘要遗漏 | 证据完整才补入 |
| 4 | 有检验没说明 | 正文有误差/敏感性/稳健性/对比，摘要未提 | 补入能改变可信度判断的检验 |
| 5 | 方法过多结果过少 | 大量解释原理流程，缺少最终答案 | 以 S/A 级信息重新设计该单元 |
| 6 | 篇幅失衡 | 简单问过长、核心问过短 | 按任务价值重分配，不维持原比例 |

出现任一型 → 基于正文重组重写，不继续以原摘要句序为骨架。

## 三、信息价值分级

- **S 级**（必须写入）：题目核心答案、核心模型、最终方案、关键量化结果。
- **A 级**（建议写入）：模型改进、重要数据处理、创新点、关键检验结果。
- **B 级**：理解主链所需的建模过程与辅助结果，只补足逻辑。
- **C 级**（删除）：普通算法原理、常规流程、背景、软件操作、附件导览、泛化评价。

句内压缩顺序：核心方法 > 关键量化结果 > 主要结论 > 有价值的创新 > 必要数据处理。S 级信息缺失时禁止用 A/B 级内容包装成答案，更禁止虚构。

## 四、数字评委判断门

每个候选数字过一门："**这个数字能否帮评委快速判断模型得出了什么、效果如何？**"保留：题目最终答案/阈值的数字、核心精度误差、目标函数值/成本/收益、优化前后变化、敏感区间/置信区间。删除：中间参数迭代值、全量坐标/权重数组、缺对象/单位/条件的孤立数字、与最终采纳值冲突的多组数值。

**每个保留数字必须带齐：对象、指标、条件、必要单位、原精度**；训练/验证/测试等口径禁混用；正文多口径冲突时沿证据链确认最终采纳值，无法确认则省略，禁止自选更优值。

## 五、篇幅基准（软边界，硬约束优先）

历年国一摘要去标记正文字符：P10=772，P25=919，**中位=1082**，P75=1211，P90=1294；段落数中位 5。**优先落在 900～1210 字符**（分问多可近上四分位）。篇幅是结果不是目标：每问闭环优先于落入区间；系统硬约束（摘要 ≤1 页）永远优先。禁止为凑长度补背景/原理；结尾不是固定配件——有跨问总体结论才单独收束，否则在最后一问自然结束。

## 六、题型主干（条件触发：按问题类型选用）

- **优化/运筹类**：决策变量与目标 → 决定性约束/不确定性 → 模型与求解策略 → 最优方案/目标值 → 基准改进或可行性验证；路径表/调度矩阵留在正文。
- **统计/假设检验类**：样本结构与检验设计 → 检验/模型 → 关键显著性/功效指标 → 样本量与阈值方案 → 诊断与结论。
- 预测类：对象与时域 → 关键处理与选模理由 → 最终模型 → 精度误差 → 预测结果。
- 评价类：对象 → 指标依据 → 综合评价方法 → 排名等级 → 一致性稳健性。
- 分类类：难点 → 特征/不平衡处理 → 验证设计与分类器 → 准确率/F1/AUC → 泛化改进。
- 机理建模类：物理假设/守恒关系 → 状态方程 → 数值求解/参数估计 → 关键状态值 → 误差与适用条件。
- 混合题按分问题分别适用，不整篇强贴单一标签。

## 七、负面规则表（快速对照）

| 低质量写法 | 修正 |
|-----------|------|
| 大段背景与意义 | 压缩为研究对象、任务冲突、必要条件 |
| 大段普通模型原理 | 只留选择理由、关键设计与求解作用 |
| 只写方法不写结果 | 回正文提取答案/指标/定性结论 |
| "效果较好""显著" | 用正文误差/收益/变化替换 |
| 堆砌模型算法名 | 定主/辅/验证角色，只留主链 |
| 强行造创新点 | 有瓶颈-设计-效果证据链才写 |
| 搬运结果表/参数向量 | 每问选 1-3 个判别力数字 |
| 重复软件/附件/图表导览 | 删除，篇幅让给答案与可信度 |
| 结尾重复各问或自我评价 | 有新总体结论才收束 |

## 八、写作决策顺序（冲突仲裁）

事实忠实与正文证据 → 每问方法-答案闭环 → S 级信息 → A 级信息 → 题型适配与衔接 → 语言紧凑与篇幅。任何风格或"国奖感"不得凌驾事实忠实度。

## 九、与系统既有惯例的衔接（一处定义，不重复）

- **加粗**：仅摘要关键词行加粗（摘要写作规范），摘要正文禁止加粗（用户裁决，本规范不引入正文加粗建议）。
- **符号就地身份**：摘要中出现的符号一律就地带身份（摘要写作规范）。
- **条件限定词保留**（惯例 二.11）、**蒙特卡洛偏差注脚**（惯例 二.27）、**跨子问题数值禁止互引**（惯例 二.28）照常执行。
- **审计产物去向**：候选池/分级表/损失六型判定写入 `review_report.json` 摘要审计字段与 `review_scores.md` 摘要专项节（内部审阅证据）；公开产物（abstract_candidates.md、论文）只含候选摘要与取舍理由，不展示审计表与中间推理。

## 十、机查执行

`check_abstract_guard.py`（code_templates）两子命令：`verify`（摘要边界外内容逐字符一致检查，边界以 `abstract:end` 锚点定位）与 `audit`（篇幅分布 WARN + 段落无数字 WARN——疑似"有方法无结果"）。执行时机与 WARN 裁定按 orchestrator 第 4 节与惯例 五.1。
